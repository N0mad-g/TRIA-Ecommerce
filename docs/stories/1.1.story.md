## Story

**As a** dev,
**I want** o projeto Next.js (App Router) inicializado com Tailwind, Framer Motion, lucide-react, deploy automático na Vercel e um gate de teste no CI,
**so that** as próximas stories tenham uma base funcional e protegida por testes antes de ir pra produção.

## Acceptance Criteria

1. Projeto Next.js (App Router, versão estável mais recente no scaffold) roda localmente (`npm run dev`) sem erros.
2. Tailwind CSS, Framer Motion e lucide-react instalados e configurados.
3. Deploy automático na Vercel a partir do branch main funcional (preview URL acessível).
4. Página inicial temporária ("health check") renderiza sem erro em produção.
5. Jest + React Testing Library + jest-axe instalados e configurados, com um teste de exemplo passando (`npm test`).
6. `README.md` documenta setup local (pré-requisitos, instalação, comandos de dev/test/build) e `.env.example` lista **os nomes** de todas as variáveis de ambiente necessárias sem valores reais.
7. Workflow `.github/workflows/test.yaml` criado, rodando `npm test`/`npm run build` em Pull Requests contra `main`.

**Regra crítica (Seção 15.1 Coding Standards):** nenhuma dessas variáveis server-only pode ganhar o prefixo `NEXT_PUBLIC_` — é a barreira técnica do Next.js contra vazamento de secret pro bundle do client.

[Source: architecture.md Seção 14 — Testing Strategy]

- **Localização de testes:** co-localizados com o código (`ComponentName.test.tsx` ao lado de `ComponentName.tsx`), padrão Jest + RTL.
- **Framework:** Jest + React Testing Library para componentes; `jest-axe` para violações de acessibilidade (`expect(await axe(container)).toHaveNoViolations()`).
- **Requisito desta story:** pelo menos 1 teste de exemplo passando, validando que a suíte de testes está funcional (`npm test` sem erro) — não precisa cobrir lógica de negócio ainda, já que a página de health-check é temporária.

### Achados Encontrados e Corrigidos Nesta Review (Active Refactoring)

1. **`app/layout.tsx` — `lang="en"` num site 100% PT-BR.** Falha real de WCAG 3.1.1 (Language of Page, nível A — mais básico que o AA que o projeto mira), não nitpick de estilo: screen reader pronuncia português com regras fonéticas de inglês. **Corrigido:** `lang="pt-BR"`.
   - **Why:** conteúdo/marca são inteiramente em português (todo o PRD é PT-BR); nunca foi decisão consciente, era boilerplate do scaffold não revisado.
   - **How:** troca de atributo de uma linha, sem risco.
2. **`app/layout.tsx` — `metadata.title`/`description` ainda "Create Next App"/"Generated by create next app".** Esse layout raiz persiste em **todas** as páginas do site (inclusive a Home real da Story 1.3), não só na página de health-check — se não corrigido agora, o título da aba do navegador ficaria errado indefinidamente até alguém notar. **Corrigido:** `title: "TRIA"`, `description: "Ciência para reconstruir sua identidade"` (tagline do PRD, não inventado).
3. **`.github/workflows/test.yaml` não rodava `npm run lint`.** Nem mesmo o exemplo original da Architecture (Seção 12.2) incluía — não é desvio do @dev, é gap que já existia na especificação. Risco real: um PR futuro poderia introduzir erro de lint (exatamente a classe de problema que o próprio @dev encontrou e corrigiu manualmente nesta story — `.aiox-core/` vazando pro linter) e o gate de CI passaria verde do mesmo jeito, porque lint nunca era checado automaticamente. **Corrigido:** adicionado `npm run lint` ao workflow, antes de `npm test`.
4. **`.gitignore` tinha `.vercel` duplicado** (linha extra adicionada automaticamente pelo `vercel link`). Cosmético, sem impacto funcional — **corrigido** por completude.

Todos os 4 achados foram corrigidos diretamente nesta review (dentro da autoridade de Active Refactoring do QA) e revalidados: `npm run lint` / `npm run build` / `npm test` rodados do zero após as mudanças — todos passando.
