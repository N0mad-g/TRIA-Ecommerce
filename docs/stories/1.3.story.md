## Story

**As a** visitante,
**I want** ver a Home com hero carrossel, seção de marca, benefícios, vitrines de protocolo/produto e depoimentos,
**so that** eu entenda a marca e possa navegar até Assinatura ou Produtos.

## Acceptance Criteria

1. Hero renderiza 3 slides com autoplay, navegação manual e dots.
2. Seção "Por que TRIA", 3 pilares de benefício e depoimentos renderizam com conteúdo do brief.
3. Vitrine de Protocolos exibe os 3 protocolos com "Ritual de Autoridade" destacado, linkando para `/assinatura`.
4. Vitrine de Produtos avulsos exibe amostra linkando para `/produtos`.
5. Layout responsivo mobile-first, validado em viewport mobile e desktop.
6. Formulário de captura de lead (slide 3 do hero) valida e-mail ou WhatsApp no client, envia para `POST /api/leads` (endpoint público) e persiste no banco. Exibe confirmação de sucesso e mensagem de erro em caso de falha de validação/rede.
7. Formulário exibe checkbox de consentimento LGPD (texto: aceite de uso do contato para comunicação da TRIA), **não pré-marcado** — botão de envio permanece desabilitado até o checkbox ser marcado.

### API Specification — `POST /api/leads`

[Source: architecture.md Seção 5 — API Specification]

```yaml
POST /api/leads
security: []  # endpoint público — mitigado por rate limit no Vercel Firewall
body: { contact: string, contactType: 'email'|'whatsapp', utmSource?: string, utmCampaign?: string, consentGiven: boolean }
responses:
  201: Lead persistido
  400: contact/contactType/consentGiven inválido
  429: Rate limit excedido (Vercel Firewall — infra, não código desta story)
```

}

### Refactoring Performed

- **File**: `supabase/rls.test.ts`
  - **Change**: Adicionados 3 testes novos (`describe('RLS — leads...')`): SELECT bloqueado por RLS (lista vazia, sem policy), INSERT com `consent_given=false` bloqueado pelo CHECK constraint do banco (`23514`), INSERT com `consent_given=true` aceito.
  - **Why**: A migration de `leads` afirma duas garantias de segurança via `COMMENT ON POLICY`/`COMMENT ON COLUMN` (RLS sem SELECT, CHECK de consentimento) que nenhum teste verificava empiricamente — mesmo padrão do achado da QA da Story 1.2 (RLS write-blocking nunca testada). Verifiquei manualmente contra o Supabase dev real antes de escrever os testes (usei `@supabase/supabase-js` diretamente — uma tentativa inicial com `fetch` cru falhou por faltar o header `Content-Profile: public` que o client oficial envia; não é bug da aplicação, é detalhe de transporte da minha verificação).
  - **How**: Mesma propriedade de segurança agora tem trava de regressão automatizada, igual ao padrão já estabelecido pra products/protocols/protocol_products.

- **File**: `components/hero/LeadForm.tsx`
  - **Change**: `submitLead({ ..., consentGiven: true })` → `submitLead({ ..., consentGiven })` (variável de estado real, não valor fixo).
  - **Why**: O componente enviava `consentGiven: true` fixo no payload, não o valor real do checkbox. Hoje o botão de envio fica desabilitado até o checkbox ser marcado, então o valor incorreto nunca chega a ser exercitado em uso normal — mas a função só é segura por causa do gate de UI (`disabled`), não porque o dado transmitido reflita o estado real. Isso viola o espírito de "defesa em profundidade" que a própria story pede pro backend/banco (AC7) e deixaria o payload mentindo sobre o consentimento se o gate de UI algum dia mudar (ex: submissão via Enter em navegadores que ignoram `disabled` do botão, ou uma refatoração futura remover o `disabled`).
  - **How**: Client agora só pode reportar o consentimento que o usuário de fato deu. Testes existentes em `LeadForm.test.tsx` continuam passando sem alteração (o fluxo de sucesso já marca o checkbox antes de submeter, então o valor real e o valor antigo hardcoded coincidem nesse caminho — a correção protege contra os caminhos que os testes atuais não cobrem).

- **File**: `.gitignore`
  - **Change**: Adicionada entrada `graphify-out/`.
  - **Why**: Artefato gerado por uma ferramenta de análise de codebase (`/graphify`) rodada nesta sessão, sem relação com a Story 1.3 — ficaria staged por acidente junto com o commit desta story se não fosse ignorado.
